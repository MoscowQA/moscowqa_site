# CLAUDE.md

Инструкции для Claude Code при работе в этом репозитории.

## Что это за проект

Статический сайт сообщества Moscow QA. Генератор — `build.py` (Python, Jinja2 + markdown), читает контент из `content/` и рендерит HTML в `dist/`.

```bash
make install           # зависимости
make build             # собрать сайт в dist/
make serve             # собрать и открыть на http://127.0.0.1:8000
make                   # список всех целей
```

`make` — просто обёртка: `python3 build.py` и остальные скрипты по-прежнему
работают напрямую.

## Структура контента

- `content/events/{номер}-{слаг}.md` — митапы. Правила добавления/обновления — см. [`EVENT_GUIDE.md`](./EVENT_GUIDE.md).
- `content/speakers/{имя-фамилия}.md` — профили спикеров. Правила — см. [`SPEAKER_GUIDE.md`](./SPEAKER_GUIDE.md).
- `templates/` — Jinja2-шаблоны страниц.
- `static/images/speakers/` — фото спикеров.

## Ключевые правила

- **Связь докладов со спикерами — по точному совпадению имени.** Значение в `talks[].speakers` в файле события должно дословно совпадать с полем `name` в `content/speakers/*.md`. Иначе доклад не свяжется с профилем.
- **Новый спикер → обязательно прогнать синхронизацию с конференциями.** Если для события создан новый файл в `content/speakers/`, сразу выполните:
  ```bash
  make sync
  ```
  Это подтягивает прошлые доклады спикера с SQA Days и Heisenbug в `external_talks`. Для уже существующих спикеров повторный прогон не обязателен.
- **Виджет Timepad подключается сам.** Если `registration_link` события ведёт на Timepad, кнопка «Зарегистрироваться» открывает форму регистрации поверх страницы — и на странице события, и на карточках в списках. ID вытаскивается из ссылки автоматически. Управляется полем `timepad_widget` (`popup` / `inline` / `false`), подробности — в [`TIMEPAD_WIDGET.md`](./TIMEPAD_WIDGET.md).
- **Фото спикеров**: приводите к размеру ~1080×1080 (как у большинства существующих фото), не заливайте оригиналы в несколько мегабайт без сжатия. Для этого есть скрипт:
  ```bash
  make photo FILE=static/images/speakers/photo.png
  ```
- После любых правок контента запускайте `make build` и убедитесь, что сборка проходит без ошибок (проверьте счётчик событий/докладов/спикеров в выводе). `make check` дополнительно проверяет синтаксис Python и что `dist/` не пустой.
- `dist/` — сгенерированная директория, в git не коммитится (см. `.gitignore`).
