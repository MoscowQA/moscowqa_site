# Инструкция для спикеров Moscow QA

Эта инструкция поможет вам добавить или обновить информацию о себе на сайте Moscow QA.

## Структура файла спикера

Каждый спикер представлен отдельным markdown-файлом в папке `content/speakers/`. Имя файла должно быть в формате `imya-familiya.md` (латиницей, маленькими буквами, через дефис).

Пример: `aleksey-ivanov.md`

## Формат файла

Файл состоит из двух частей:
1. **YAML front matter** (метаданные между `---`)
2. **Биография** (текст после метаданных)

### Полный пример

```markdown
---
name: "Алексей Иванов"
company: "2ГИС"
photo: "https://storage.yandexcloud.net/barbez/speaker/aleksey-ivanov.png"
telegram: "alexey_qa"
github: "dragin96"
twitter: "dragin96"
website: "https://example.com"
external_talks:
  - title: "Архитектура читаемых автотестов"
    event: "Heisenbug"
    date: "2024-11-15"
    url: "https://www.youtube.com/watch?v=example"
    slides_url: ""
---

Увлекаюсь тестированием и ценю качество продуктов. Особенно по душе писать код, который проверяет код, а также заниматься программированием ради удовольствия.
Основатель сообщества по тестированию MoscowQA, где организуют митапы. Веду Telegram-канал о тестировании.
```

## Описание полей

### Обязательные поля

| Поле | Описание | Пример |
|------|----------|--------|
| `name` | Ваше имя и фамилия | `"Алексей Иванов"` |
| `company` | Текущая компания | `"2ГИС"` |
| `photo` | URL к вашему фото | `"https://storage.yandexcloud.net/barbez/speaker/aleksey-ivanov.png"` |

### Необязательные поля (социальные сети)

Вы можете добавить ссылки на свои социальные сети и сайт. Если не хотите указывать какую-то соцсеть, просто оставьте пустые кавычки `""` или не указывайте это поле.

| Поле | Описание | Формат | Пример |
|------|----------|--------|--------|
| `telegram` | Telegram username (без @) | username | `"dragin96"` |
| `github` | GitHub username | username | `"dragin96"` |
| `twitter` | Twitter/X username (без @) | username | `"dragin96"` |
| `website` | Личный сайт или блог | полный URL | `"https://example.com"` |

**Важно:** Для Telegram, GitHub и Twitter указывайте только username без @ и без ссылок. Ссылки сформируются автоматически.

### Биография

После метаданных (после второго `---`) напишите краткую биографию:
- 1-3 предложения
- Текущая должность и компания
- Основные интересы/специализация в QA
- Без лишних подробностей

**Примеры:**

✅ Хорошо:
```
Automation QA в 2ГИС, основатель сообщества Moscow QA. Занимается вопросами производительности и инструментами разработчика в браузере.
```

✅ Хорошо:
```
Head of QA в Garage Eight. Специализируется на построении процессов обеспечения качества в продуктовых командах.
```

❌ Плохо (слишком подробно):
```
Работаю QA с 2010 года. Начинал мануальным тестировщиком в маленьком стартапе, потом перешел в автоматизацию. Изучал Java, потом Python, сейчас в основном TypeScript. Работал в 5 компаниях. Люблю путешествовать и играть в футбол.
```

## Доклады и выступления

### Как добавляются доклады

**Важно:** Доклады на митапах Moscow QA добавляются автоматически организаторами в файлы событий. Вам не нужно ничего делать дополнительно.

После того, как вы выступите на митапе:
1. Организаторы добавят информацию о вашем докладе в файл события
2. Доклад автоматически появится на вашей странице спикера
3. У доклада будет своя отдельная страница со ссылкой на видео (если есть)

### Что будет указано в докладе

Для каждого доклада указывается:
- **Название доклада** - как анонсировалось на митапе
- **Описание** - краткое содержание (1-2 предложения)
- **Событие** - на каком митапе был доклад
- **Компания** - в какой компании вы работали на момент выступления
- **Видео** - ссылка на запись (если есть)
- **Слайды** - ссылка на презентацию (если есть)

### Внешние выступления

Если вы выступали на других конференциях или митапах (не Moscow QA), вы можете добавить их в структурированном виде с помощью секции `external_talks`.

#### Формат external_talks

```markdown
---
name: "Константин Волков"
company: "Flipper Devices"
photo: "https://storage.yandexcloud.net/barbez/speaker/volkov.png"
external_talks:
  - title: "Тестируем Flipper Zero: от прототипа до конвейера"
    event: "Heisenbug"
    date: "2024-11-15"
    url: "https://www.youtube.com/watch?v=example"
    slides_url: "https://example.com/slides.pdf"
  - title: "357 подготовленных докладчиков"
    event: "TeamLead Conf"
    date: "2024-09-10"
    url: ""
    slides_url: ""
---

QA manager в Flipper Devices.
```

#### Поля для внешних докладов

| Поле | Обязательное | Описание | Пример |
|------|--------------|----------|--------|
| `title` | ✅ Да | Название доклада | `"Тестируем Flipper Zero"` |
| `event` | ✅ Да | Название конференции/митапа | `"Heisenbug"`, `"TeamLead Conf"`, `"QA Fest"` |
| `date` | ⚪ Нет | Дата выступления (YYYY-MM-DD) | `"2024-11-15"` |
| `url` | ⚪ Нет | Ссылка на запись доклада | `"https://www.youtube.com/watch?v=..."` |
| `slides_url` | ⚪ Нет | Ссылка на слайды | `"https://example.com/slides.pdf"` |
| `description` | ⚪ Нет | Краткое описание (1-2 предложения) | `"О построении системы подготовки докладчиков"` |

**Важно:**
- Если у вас нет ссылки на видео или слайды, оставьте пустые кавычки `""`
- Дата в формате `YYYY-MM-DD` (например: `2024-11-15`)
- Можно добавить любое количество докладов

#### Как это будет выглядеть

На вашей странице появится отдельная секция **"Внешние выступления"** после докладов Moscow QA:
- Название конференции (бейдж)
- Дата
- Название доклада
- Описание (если указано)
- Ссылки на запись и слайды (если указаны)

В статистике будет показано:
- Общее количество докладов
- "X на Moscow QA"
- "X на других площадках"

#### Альтернатива: упоминание в биографии

Если у вас 1-2 выступления без ссылок, можно просто упомянуть их в биографии:

```markdown
---
name: "Алексей Иванов"
company: "2ГИС"
photo: "https://storage.yandexcloud.net/barbez/speaker/aleksey-ivanov.png"
---

Automation QA в 2ГИС, основатель сообщества Moscow QA.

Выступал на конференциях: Heisenbug, QA Fest, TeamLead Conf.
```
