# Инструкция по добавлению событий Moscow QA

Эта инструкция описывает, как добавлять и обновлять митапы на сайте Moscow QA.

## Структура файла события

Каждое событие — отдельный markdown-файл в папке `content/events/`. Имя файла:

```
{номер}-{слаг-компании}.md
```

Номер — порядковый номер митапа (сквозной, не сбрасывается). Слаг — латиницей, через дефис, обычно название компании-хоста. Если компания принимает митап уже не в первый раз, добавляйте суффикс `-2`, `-3` и т.д.

Примеры: `15-school21.md`, `20-school21-2.md`, `26-school21-3.md`.

Для **ненумерованных активностей** (например, шорт-трек сообщества на чужой конференции) номер не используется — имя файла состоит только из слага, а поле `number` в front matter не указывается. Вместо номера на карточке и в шапке страницы показывается картинка сбоку — путь к ней задаётся полем `cover`.

Пример: `heisenbug-2026-spring.md`.

## Формат файла

Файл состоит из двух частей:
1. **YAML front matter** (метаданные между `---`)
2. **Тело** (markdown-текст после метаданных: таймин, площадка, билеты и т.д.)

### Полный пример

```markdown
---
title: "Moscow QA #26 x «Школа 21»"
number: 26
date: "2026-07-16"
company: "Школа 21"
address: "Москва, Вятская улица, 27с42, БЦ «Фактория»"
type: "Offline + Online"
short_description: "Юбилейный митап совместно со «Школой 21». Доклады про AI Driven Quality Gates и тестирование прошивок для спутников."
registration_link: ""
video_link: ""
photos_link: ""
talks:
  - title: "AI Driven Quality Gates"
    speakers:
      - "Владимир Михайлов"
    company: "Head of QA"
    description: "Как AI помогает создавать, встраивать и развивать Quality Gates на всех этапах SDLC."
---

16 июля 2026 года вместе со «Школой 21» пройдет юбилейный митап Moscow QA #26.

## Тайминг:

- 18:30 — 19:00 — начало регистрации
- 19:05 — 19:30 — AI Driven Quality Gates, Владимир Михайлов

## Площадка:

Встреча пройдет по адресу: Москва, Вятская улица, 27с42, БЦ «Фактория»

## Категории билетов

**Онлайн-формат**

Регистрироваться не надо, следите за нашим каналом [moscowqa](https://t.me/moscowqa)

**Офлайн-формат**

Так как количество мест ограничено, в офлайн смогут попасть не все.

**С собой надо обязательно иметь паспорт или ВУ**

Следите за нашими анонсами в информационных каналах: [telegram](https://t.me/moscowqa) и [telegram chat](https://t.me/moscowqa_chat), а также [YouTube](https://www.youtube.com/@moscowqa)
```

## Описание полей front matter

### Обязательные поля

| Поле | Описание | Пример |
|------|----------|--------|
| `title` | Заголовок события | `"Moscow QA #26 x «Школа 21»"` |
| `number` | Порядковый номер митапа (число). Не указывается для ненумерованных активностей — тогда нужен `cover` | `26` |
| `date` | Дата в формате `YYYY-MM-DD` | `"2026-07-16"` |
| `company` | Компания-хост | `"Школа 21"` |
| `type` | Формат: `"Offline"`, `"Online"` или `"Offline + Online"` | `"Offline + Online"` |

### Необязательные поля

| Поле | Описание | Пример |
|------|----------|--------|
| `address` | Адрес площадки (для офлайн/гибрид) | `"Москва, Вятская улица, 27с42, БЦ «Фактория»"` |
| `time` | Время начала в формате `"ЧЧ:ММ"` (обязательно в кавычках, иначе YAML прочитает его как число). Идёт в файл календаря и в разметку для поисковиков; без него событие считается идущим весь объявленный день | `"19:00"` |
| `end_time` | Время окончания, тоже в кавычках. Без него митап считается идущим до 22:00 — указывать надо, только если этот раз заканчивается не как обычно | `"23:00"` |
| `short_description` | Краткое описание для SEO/превью (1-2 предложения) | `"Юбилейный митап совместно со «Школой 21»..."` |
| `registration_link` | Ссылка на регистрацию (обычно Timepad). Пусто `""`, пока нет ссылки | `"https://moscowqa.timepad.ru/event/..."` |
| `video_link` | Ссылка на трансляцию/плейлист записи. Пусто, пока события не было | `"https://youtube.com/..."` |
| `photos_link` | Ссылка на альбом с фото после митапа | `""` |
| `cover` | Обложка события — путь к картинке в `static/images/events/`. Показывается сбоку вместо номера, поэтому обязательна для событий без `number`. Заодно заменяет собой картинку превью для ссылок (см. «Превью ссылки в соцсетях» ниже) | `"/static/images/events/heisenbug-2026-spring.jpg"` |
| `cover_desktop` | Вариант обложки для широких экранов (от 1024px). Нужен, когда одна картинка плохо смотрится и в узкой полосе на мобильном, и в высоком блоке на десктопе. Без него везде показывается `cover` | `"/static/images/events/heisenbug-2026-spring-web.jpg"` |

После того как положили картинку в `static/images/events/`, прогоните
`make covers` — рядом появятся webp-варианты на 540/768px и в полный размер,
и браузер будет качать подходящий вместо одного большого JPEG на все случаи.
Исходник никуда не девается: на него указывает `cover`, и он же уходит в
og:image, куда webp кладут не все соцсети. Забыли прогнать — `make validate`
напомнит замечанием.
| `timepad_event_id` | ID события в Timepad. Указывать нужно, только если регистрация идёт не через Timepad, а виджет нужен | `"4046132"` |
| `timepad_widget` | Как показывать виджет регистрации Timepad: `popup` (форма поверх страницы по клику, по умолчанию), `inline` (форма внизу страницы) или `false` (выключить) | `inline` |

### Превью ссылки в соцсетях

Когда ссылку на событие кидают в Telegram, VK или ищут в поиске, там
показывается картинка — та, что лежит в `og:image`. Рисовать её не надо:
сборка сама собирает карточку 1200×630 из front matter — номер митапа и
формат, дата, название, адрес с компанией-хостом и спикеры с их компаниями.

Ничего для этого дописывать не нужно: добавили событие, прогнали
`make build` — карточка появилась в `dist/static/og/events/{слаг}.png`.

Посмотреть, что получилось, не пересобирая сайт:

```bash
make og                   # все события в og-preview/
make og ARGS="28-black"   # только одно
```

Что стоит знать:

- **Спикеров на карточке максимум четыре**, остальные сворачиваются в
  «и ещё N спикеров» — больше в превью Telegram всё равно не прочитать.
  Если спикеров много, первыми идут те, чьи доклады выше в `talks`.
- **Компания берётся из профиля спикера** (`content/speakers/*.md`), а не из
  `talks[].company`: там нередко стоит должность вроде «Head of QA».
- **Длинное название съедает место**: оно занимает до трёх строк, и чем
  больше строк, тем меньше спикеров влезет. Если состав важнее — название
  стоит сократить.
- **Своя картинка важнее сгенерированной.** Если у события заполнен `cover`,
  в превью пойдёт он, а карточка не рисуется.

### «Добавить в календарь»

Для каждого события сборка кладёт рядом со страницей файл
`events/{слаг}/event.ics`, а на странице появляется карточка «В календарь» с
кнопками «Скачать .ics» и «Google Календарь». Ничего указывать не нужно —
достаточно поля `date`.

Без поля `time` запись получается на весь день: это честно отражает «объявили
дату, но не час». Если время известно, добавьте `time` — и в календарь попадёт
нормальный интервал: с указанного часа до 22:00, как обычно заканчиваются
митапы. `end_time` нужен, только когда этот раз заканчивается не в 22:00.
Время считается московским, в файл оно записывается в UTC.

Те же границы уходят в разметку для поисковиков (`startDate`/`endDate`).

Карточка показывается только у предстоящих событий.

### Виджет регистрации Timepad

Если `registration_link` ведёт на Timepad, кнопка «Зарегистрироваться»
открывает форму регистрации поверх страницы — и на странице события, и на
карточках в списках (главная, `/events/`). ID события вытаскивается из
ссылки, и ничего дописывать не нужно. Поля `timepad_widget` и
`timepad_event_id` нужны только для нестандартных случаев (форма прямо в теле
страницы, регистрация на сайте партнёра, отключение виджета). Подробности — в [`TIMEPAD_WIDGET.md`](./TIMEPAD_WIDGET.md).

**Важно:** поле `completed` больше не используется в front matter — прошедшее/будущее состояние события определяется на фронтенде по полю `date` (см. `static/js/events-status.js`). Добавлять его не нужно.

## Доклады (`talks`)

`talks` — список докладов митапа, в порядке выступления.

| Поле | Обязательное | Описание |
|------|--------------|----------|
| `title` | ✅ Да | Название доклада |
| `speakers` | ✅ Да | Список имён спикеров (обычно один). Формат — `"Имя Фамилия"` |
| `company` | ⚪ Нет | Компания спикера на момент доклада |
| `description` | ⚪ Нет | Краткая аннотация доклада (1-3 предложения) |
| `tags` | ⚪ Нет | Темы доклада — список из 1–3 тегов. По ним собираются страницы `/tags/{тема}/` |
| `record` | ⚪ Нет | Ссылка на запись именно этого доклада (если есть отдельная, помимо общего `video_link`) |
| `slides_url` | ⚪ Нет | Ссылка на слайды доклада |
| `slug` | ⚪ Нет | Ручной URL-слаг доклада. Если не указан, генерируется автоматически транслитерацией `title` |

### Темы (`tags`)

Теги раскладывают доклады по темам: для каждого собирается страница
`/tags/{слаг}/`, а список всех тем — на `/tags/`. Пишутся строкой прямо
после названия доклада:

```yaml
talks:
  - title: "Архитектура читаемых тестов на Playwright"
    tags: ["автоматизация"]
```

Берите теги из уже существующих — иначе вместо общей страницы получится
несколько почти одинаковых. Сейчас в ходу:

`автоматизация`, `карьера`, `процессы качества`, `софт-скиллы`, `AI и LLM`,
`истории и факапы`, `инструменты`, `инфраструктура`,
`выступления и сообщество`, `железо и устройства`, `команда и лидерство`,
`фронтенд`, `API и интеграции`, `нагрузочное тестирование`, `безопасность`,
`ручное тестирование`.

Новый тег заводится, только если доклад действительно не попадает ни в одну
из тем. Один-два тега на доклад — нормально, три — уже много. Регистр и
лишние пробелы не важны: теги с одинаковым слагом попадают на одну страницу.
Доклад без тегов просто не появится в темах.

**Критически важно:** значение в `speakers` должно **дословно совпадать** с полем `name` в файле спикера (`content/speakers/*.md`) — сопоставление идёт по точному совпадению строки. Если имя не совпадёт (опечатка, другой порядок слов, инициалы вместо имени), доклад не свяжется с профилем спикера и не появится на его странице.

- Перед добавлением доклада проверьте, есть ли уже файл спикера в `content/speakers/`.
- Если файла нет — создайте его по инструкции в [`SPEAKER_GUIDE.md`](./SPEAKER_GUIDE.md).
- Если слот ещё не анонсирован, в теле файла (в разделе `## Тайминг:`) можно указать `не анонсировано` вместо названия доклада и спикера — сам доклад в `talks` при этом не добавляется.

## Тело файла (markdown после front matter)

Обычно тело события состоит из следующих разделов (используйте `##` для заголовков):

1. Вступительный абзац — дата, повод, компания-хост.
2. `## Тайминг:` — список `HH:MM — HH:MM — Название доклада, Имя Фамилия` (или `начало регистрации` / `перерыв` / `не анонсировано`).
3. `## Площадка:` — адрес и формат (для офлайн/гибрид).
4. `## Категории билетов` — подпункты **Онлайн-формат** / **Офлайн-формат** с условиями участия.
5. Финальная строка со ссылками на каналы анонсов (telegram, telegram chat, YouTube).

Держите формулировки близкими к уже опубликованным событиям — это единообразие ценится больше, чем разнообразие стиля.

## Чек-лист при добавлении/обновлении события

1. Создайте/обновите файл `content/events/{номер}-{слаг}.md` по шаблону выше.
2. Для каждого спикера убедитесь, что есть файл в `content/speakers/` с точным совпадением `name`. Если файла нет — создайте его по [`SPEAKER_GUIDE.md`](./SPEAKER_GUIDE.md).
3. Если у события появились новые доклады — не забудьте обновить `## Тайминг:` в теле файла.
4. **Если хотя бы один спикер новый** (только что создан файл в `content/speakers/`) — обязательно прогоните синхронизацию внешних докладов с SQA Days и Heisenbug, чтобы подтянуть его прошлые выступления:
   ```bash
   python3 parsers/sync_sqadays.py
   python3 parsers/sync_heisenbug.py
   ```
   Для уже существующих спикеров это не требуется — актуальные данные уже синхронизированы ранее.
5. Запустите сборку и проверьте, что всё сгенерировалось без ошибок и доклады связались со спикерами:
   ```bash
   python3 build.py
   ```
   В выводе есть строка `Timepad widget: N/M events` — по ней видно, подхватился ли виджет регистрации для нового события, и строка `OG covers: N generated` — сколько нарисовано карточек для превью ссылок.
6. Посмотрите, как событие будет выглядеть ссылкой в Telegram (см. [«Превью ссылки в соцсетях»](#превью-ссылки-в-соцсетях)):
   ```bash
   make og ARGS="29-имя-события"
   ```
   Если длинное название вытеснило с карточки спикеров — название стоит сократить.
7. Закоммитьте изменения в `content/events/` (и `content/speakers/`, если добавляли/правили профиль).
