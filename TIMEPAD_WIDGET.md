# Виджеты Timepad на сайте

Сайт умеет встраивать [виджеты Timepad](https://dev.timepad.ru/widget/what-widget-can/):
форму регистрации на странице события и афишу предстоящих событий организации.
Виджет регистрации включён для всех событий, у которых регистрация идёт через
Timepad, — отдельно настраивать ничего не нужно. По умолчанию форма открывается
попапом поверх страницы, чтобы не отправлять посетителя прокручивать страницу
мимо программы.

## Как это устроено

Три слоя:

| Файл | Отвечает за |
|------|-------------|
| `build.py` | Достаёт ID события Timepad из `registration_link`, решает, в каком режиме показывать виджет, и кладёт настройки в `site.timepad_widget` |
| `templates/partials/timepad.html` | Макросы `registration()` и `event_list()` — рендерят плейсхолдер с настройками в `data-timepad-config` |
| `static/js/timepad-widget.js` | Собирает [код вставки](https://dev.timepad.ru/widget/how-widget-works/) и подставляет его в плейсхолдер |

Сам `<script>` с загрузчиком Timepad в HTML не попадает — его добавляет JS.
Благодаря этому:

- **на прошедших событиях виджет не грузится вообще** (страница архива не тянет
  сторонний скрипт);
- виджет подключается, только когда блок появляется в зоне видимости, — загрузчик
  Timepad не конкурирует с ресурсами самой страницы;
- пока виджет не отрисовался (и если JS выключен), на его месте видна обычная
  ссылка на страницу события в Timepad.

Прошедшее/предстоящее определяется в браузере по дате события — так же, как в
`static/js/events-status.js`.

## Виджет регистрации

### Когда он появляется

Виджет рендерится, если у события есть ID в Timepad. ID берётся автоматически из
`registration_link`, когда ссылка ведёт на Timepad:

```yaml
registration_link: "https://moscowqa.timepad.ru/event/4046132/"   # → ID 4046132
```

Если регистрация идёт через сайт партнёра, а событие при этом заведено и в
Timepad, ID можно указать явно:

```yaml
registration_link: "https://partner.ru/qameetup"
timepad_event_id: "4046132"
```

Событиям без ID (`registration_link` пустой или ведёт не на Timepad) виджет не
рендерится — на странице остаётся обычная карточка «Регистрация» со ссылкой.

### Режимы (`timepad_widget`)

| Значение | Что делает |
|----------|------------|
| не указано | режим по умолчанию — `popup` |
| `popup` | форма открывается поверх страницы по клику на карточку «Регистрация». Если виджет не загрузился, тот же клик открывает страницу события в Timepad в новой вкладке |
| `inline` | форма встроена в страницу, внизу — после блока «Доклады». Кнопка «Зарегистрироваться» в карточке вверху прокручивает к ней (`#registration`) |
| `false` | виджет выключен, остаётся только ссылка на Timepad |

```yaml
timepad_widget: inline    # или popup / false
```

Триггером попапа служит карточка «Регистрация» — Timepad навешивает обработчик
на элементы по селектору `.js-timepad-trigger` (`TIMEPAD_TRIGGER_SELECTOR`).
Чтобы попап открывался ещё откуда-нибудь, достаточно повесить этот класс на
нужную ссылку или кнопку.

## Виджет афиши (список событий)

Макрос `event_list()` подключён на странице `/events/` и выключен по умолчанию.
Чтобы включить, нужен числовой ID организации в Timepad:

```bash
TIMEPAD_ORG_ID=12345 TIMEPAD_LIST_WIDGET=1 python3 build.py
```

ID организации виден в личном кабинете Timepad (или в коде афиши, который там же
можно получить — см. [инструкцию](https://dev.timepad.ru/widget/add-events-widget/)).
В афише показываются только предстоящие публичные события организации.

## Переменные окружения

Все — необязательные; значения по умолчанию подходят для боевой сборки.

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `TIMEPAD_WIDGET` | `1` | Общий выключатель. `0` — не рендерить виджеты вообще |
| `TIMEPAD_WIDGET_MODE` | `popup` | Режим для событий, где `timepad_widget` не указан |
| `TIMEPAD_CUSTOMIZATION_ID` | пусто | ID кастомизации Timepad (оформление и поведение виджета). Пусто — стандартное оформление |
| `TIMEPAD_ORG_ID` | пусто | ID организации, нужен только для афиши |
| `TIMEPAD_LIST_WIDGET` | `0` | Включить афишу на `/events/` |
| `TIMEPAD_LOCALE` | `ru` | Язык виджета (`ru` или `en`) |
| `TIMEPAD_TRIGGER_SELECTOR` | `.js-timepad-trigger` | Селектор элементов, открывающих виджет в режиме `popup` |
| `TIMEPAD_LOADER` | `https://timepad.ru/js/tpwf/loader/min/loader.js` | Адрес загрузчика. Менять нужно разве что для локальных проверок |

Сборка печатает, сколько событий получили виджет:

```
Built 28 events, 97 talks, 88 speakers, 4 pages
Timepad widget: 13/28 events, list widget off
```

## Оформление

Внешний вид виджета задаётся на стороне Timepad через ID кастомизации — его
делают и меняют сотрудники Timepad, код вставки при этом трогать не нужно.
Часть можно перекрасить и своими стилями, передав их в настройке `loadCSS`
(см. [«Перекрасить с помощью CSS»](https://dev.timepad.ru/widget/change-css/)).
Настройки виджета собираются в макросах `templates/partials/timepad.html` —
полный список параметров есть в документации Timepad:
[виджет регистрации](https://dev.timepad.ru/widget/registration-widget-settings/),
[виджет списка событий](https://dev.timepad.ru/widget/list-widget-settings/).

Стили обёртки живут в `static/css/styles.css`, блок `=== Timepad widget ===`.

## Проверка после изменений

```bash
python3 build.py
```

Виджет грузится с сайта Timepad, поэтому увидеть его целиком можно только на
задеплоенной или локально поднятой странице (`make serve`), и только для
события, дата которого ещё не прошла. Если виджет не загрузился, регистрация
всё равно доступна: в режиме `popup` карточка открывает страницу события в
Timepad, в режиме `inline` на месте формы остаётся ссылка на неё. Это штатное
поведение, а не поломка вёрстки.
